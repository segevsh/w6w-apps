# ServiceTitan

Customers, service locations, leads, jobs, appointments and the people who run them, on the
**ServiceTitan v2 REST API** (`api.servicetitan.io`).

## Actions (17)

| Module   | Actions                                                                                  |
| -------- | ---------------------------------------------------------------------------------------- |
| CRM      | `customer-list`, `customer-get`, `customer-create`, `customer-update`                    |
|          | `location-list`, `location-create`, `lead-list`, `lead-create`                           |
| Jobs     | `job-list`, `job-get`, `job-create`, `job-cancel`, `job-note-create`, `appointment-list` |
| Settings | `technician-list`, `business-unit-list`, `employee-list`                                 |

Out of scope for this pass: accounting, pricebook, inventory, payroll, memberships, marketing,
telecom, forms, reporting and webhooks. Each is its own module in the vendor's API.

## Authentication

OAuth2 **client credentials** plus an application key. Register an app in the ServiceTitan developer
portal, have the tenant install it, then connect with the **Client ID**, **Client Secret**, **App
Key** and numeric **Tenant ID**. Every call carries `Authorization: Bearer …` and `ST-App-Key: …`;
both are stamped in `sign`, never by an action. The token is minted at `{auth host}/connect/token`
(form-encoded) and has no refresh token, so `refresh` re-mints it.

`Environment` selects the host pair: production (`api.` / `auth.servicetitan.io`) or the integration
sandbox (`api-integration.` / `auth-integration.servicetitan.io`). Credentials are not shared
between them.

## Health checks

- `service` — `status.servicetitan.com` (Atlassian Statuspage, page id pinned). Only the **Core
  Product Features** components decide the verdict; telephony, SMS, Fleet Pro and the rest are
  detail.
- `api` — unsigned request to the connection's own API host; the schema-correct `401` ProblemDetails
  ("Application key not present") proves the gateway is serving.
- `quota` — declared unavailable at informational severity: no rate-limit header or usage endpoint
  is documented.

## Verification

Everything here was checked on 2026-10-06 against the OpenAPI 3.1 documents the developer portal
serves (`developer.servicetitan.io/api/docs/apis/tenant-{crm,jpm,settings,dispatch}-v2`) and live
unsigned probes of both API hosts, both token hosts and the status page. **Not verified live:** a
successful token exchange and any authenticated call — no ServiceTitan credentials were available.
The token request shape (form-encoded client_credentials, default 900 s lifetime when `expires_in`
is absent) follows the spec's `clientCredentials` flow and the endpoint's observed
`400 {"error":"invalid_client"}`.

## Icon

`assets/icon.svg` is the `st-glyph` symbol from ServiceTitan's own brand sprite
(`www.servicetitan.com/static/brand-static-sprite.*.svg`, viewBox `0 0 39 36`), unmodified except
that the sprite's single white ink is re-inked black so it reads on the light tile.
`assets/icon.dark.svg` is the same artwork in white (generated by `_tools/icon-legibility.ts fix`).
The vendor serves no standalone SVG, `apple-touch-icon` or simple-icons entry; its favicon is a
raster `.ico`.
